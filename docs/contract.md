# Shared contracts

Backend package: `backend`. Python >=3.11, Tree-sitter JS/TS bindings plus the standard library. All dictionaries serialize to JSON.

Analyzer function: `backend.analyzer.analyze_sources(base_sources: dict[str,str], head_sources: dict[str,str], changed_paths: list[str], renames: dict[str,str] | None = None) -> dict`. Paths are POSIX repository-relative. Returns `{nodes: Symbol[], edges: CallEdge[], warnings: string[], architecture: Architecture}`.

Symbol: `{id: string, path: string, module: string, qualname: string, name: string, className: string|null, kind: 'function'|'method'|'component'|'hook'|'callback', language?: 'python'|'javascript'|'typescript', status: 'added'|'modified'|'removed'|'unchanged'|'moved'|'moved_modified', basePath: string|null, headPath: string|null, baseId?: string, base: Version|null, head: Version|null, diff: string, unresolvedCalls: UnresolvedCall[]}`.
Version: `{startLine: number, endLine: number, code: string, signature: string}`. Include decorators in code and startLine. Symbol id is `path:qualname`, using the head path when a move is reconciled; baseId retains the previous identity. Git-proven renamed files allow qualname matching, otherwise moves require unique identical structural bodies on both sides. Anonymous callbacks are matched across renamed files only when structurally identical.
UnresolvedCall: `{expression: string, line: number, reason: string}` (head, or base for removed symbols). Preserve unresolved variable dispatch; no guessing by name.
CallEdge: `{relation?: 'call'|'render'|'callback', id: string, source: string, target: string, expression: string, baseExpression: string|null, headExpression: string|null, line: number, basePath: string|null, headPath: string|null, baseLine: number|null, headLine: number|null, inBase: boolean, inHead: boolean, status: 'added'|'removed'|'unchanged', evidence: {path: string,line: number,side: 'base'|'head',expression: string}}`. Source/target are Symbol IDs. Multiple calls between a source and target may aggregate if expression matches, with one precise representative evidence site. Line and expression represent head when present, otherwise base; versioned labels and call-site evidence use the matching side's line and expression. Cross-version alignment must not classify an edge as changed only because its line moved. Method diffs use method-relative unified hunk coordinates; the frontend offsets these by the version's startLine for file-absolute display.

`POST /api/analyze` JSON `{prUrl?:string,repoPath?:string,baseRef?:string,headRef?:string,scope?:string,includeTests?:boolean,force?:boolean}` -> `{jobId:string}`. GitHub URL required except explicit local mode where repoPath + baseRef + headRef required.
`POST /api/files/read` JSON `{analysisId:string,path:string}` -> `{path:string,base:{path:string,code:string,startLine:1}|null,head:{path:string,code:string,startLine:1}|null,diff:string}`. `meta.analysisId` is an opaque server-owned descriptor for pinned Git snapshots and displayed file paths. Full source includes file-level declarations and imports; source reading is independent of graph indexing. Renames retain both paths; dependencies and excluded changed text files remain readable. Reads reject traversal, unlisted paths, symlinks, non-UTF-8/binary content and versions over 1 MiB. Private descriptors remain under `.cache/file-analyses/`; local repository paths are never sent to the browser. Existing Host/Origin and JSON-body protections apply.
`GET /api/jobs/:id` -> `{id:string,status:'queued'|'running'|'complete'|'error',stage:string,error?:string,result?:Analysis}`.
`GET /api/health` -> `{ok:true,githubAuthenticated:null,githubAvailable:boolean,githubMessage:string}`. Health checks CLI availability; repository access is checked by the analysis job.

Analysis: analyzer data plus `{meta: {title:string,prUrl:string|null,number:number|null,repository:string,baseSha:string,headSha:string,baseRef:string,headRef:string,mode:'github'|'local',scopes:string[],indexedFiles:number,changedFiles:number,analyzedAt:string,limited:boolean,includeTests:boolean},files: {path:string,previousPath?:string,status:string,changedMethods:number,indexed:boolean}[]}`. indexed is true when supported source was included from either snapshot; excluded source files must not be described as having no method changes. scopes are honest coverage boundaries. ChangedFiles includes all file types. Exact GitHub URLs can use meta.repository + pinned SHAs + node path + version line. Local mode must say local comparison, not live PR.

Frontend uses relative `/api/` routes. Vite proxy to `127.0.0.1:8765`. Dev UI at `127.0.0.1:5173`; production served by Python from dist at `127.0.0.1:8765`.

JS/TS callback edges represent function references, not invocations. Render edges represent JSX component references. Missing relation means call for backward compatibility. JS/TS source coordinates come directly from Tree-sitter UTF-8 ranges. Custom aliases and inferred receiver types are not resolved.

## Architecture overview

`Architecture = {layers, nodes, edges, features, summaries}`. The model is derived from the same pinned snapshots as method detail. It does not assert execution order or runtime coverage.

- Layer: `{id,label,description}`. Ordered IDs: `ui`, `client_state`, `server_state`, `services`, `integrations`, `supporting`, `other`.
- File node: `{id:'file:'+headOrOnlyPath,path,label,status,base:FileVersion|null,head:FileVersion|null,symbolIds:string[]}`. Each version retains its own path and classification; moved statuses follow full-file structure.
- FileVersion: `{path,roles:string[],layer,reason,indexed:boolean,facts:Evidence[],operations:{id,label,kind,line}[]}`. `reason` distinguishes syntax/import evidence from directory conventions. Files may have multiple role tags. Unindexed supporting files have no fabricated operations or relationships.
- Evidence: `{path,line,expression,kind,reason,symbolId:string|null,targetSymbolId?:string|null,startLine,code}`. Paths/lines/snippets belong to the indicated snapshot; symbol IDs use canonical head identities. `targetSymbolId` constrains facade delegation to an explicitly referenced operation.
- Edge: `{id,source,target,relation,inBase,inHead,status,baseEvidence:Evidence[],headEvidence:Evidence[]}`. Source/target are file IDs. Relations: `renders`, `runs_query`, `mutates`, `reads_store`, `calls_store_action`, `updates_store`, `calls_service`, `calls_api`, `delegates`, `calls`, `imports`. Store function calls use neutral `calls_store_action`; only explicit `setState` is labeled `updates_store`. Named `queryFn`/`mutationFn` references create registration edges without claiming immediate execution. Runtime imports are fallback context, not invocations; type-only imports do not create them. Multiple semantic relationships may exist per file pair; the map draws one strongest relationship and the file inspector retains all connections.
- Feature: `{id,root,label}`; changed screens are preferred, otherwise changed service roots. Summary: `{id,title,body,fileIds}`; deterministic counts and move/removal facts.

The default feature map follows semantic dependencies forward, filters supporting and unchanged UI/unclassified utility context, and limits a facade to the operations referenced by incoming call evidence. Import context is optional. The change inventory is independent of the map and snapshot filter so removed files stay discoverable. A file absent from the chosen snapshot shows its available version with an explicit notice.


## Review comments

`POST /api/reviews/context` accepts `{prUrl,baseSha,headSha}` and returns `{files:[{path,previousPath:string|null,baseLines:number[],headLines:number[]}]}` from current GitHub patch hunks. It validates the PR head and merge base. Lines outside available patches cannot be inline comments.

`POST /api/reviews/refresh` is read-only and accepts `{prUrl,baseSha,headSha,comments?:[{id,path,side:'base'|'head',line,baseSha,headSha}],reviewed?:[{id,path,baseSha,headSha}]}`. Top-level SHAs describe the displayed analysis; item SHAs describe each original saved comparison. It returns the latest validated open PR `{baseSha,headSha,files,comments:[{id,status,path,side,line,reason}],reviewed:[{id,status,path,reason}]}` with one result per item and status `ready` or `needs_attention`.

Read-only refresh verifies complete regular-file Git blob identities through immutable commit/tree APIs. Comments require the original snapshot side's content to match the latest side and the same line to remain in the latest diff; viewed markers require both Before and After identities, including proven absence for added/deleted files, to match. Only unambiguous explicit PR rename mappings are followed. Changed, missing, unavailable, truncated, or ambiguous content stays saved for attention. PR tips are checked again after the reads; racing commits reject the check. Refresh allows up to 2,000 records per list, opaque IDs up to 4,096 characters, and a 1 MiB HTTP body; other routes retain the 64 KiB limit.

`POST /api/reviews/submit` adds `{body?:string,comments:[{path,side:'base'|'head',line:number,body:string}]}`. The service revalidates context, maps Before paths of renames to GitHub canonical paths and LEFT/RIGHT sides, then creates one COMMENT review on the pinned head. Up to 50 nonempty comments, 10,000 characters per comment/summary, and the existing 64 KiB HTTP request limit apply. Returns `{id,url}`. Errors use `{error,ambiguous?:boolean}` with relevant HTTP status; drafts remain in the browser.

Completed submission payloads are deduplicated with a persistent hashed receipt; pending/ambiguous receipts return `ambiguous:true` and cannot be resent automatically. Definite rejected writes remove the receipt so permissions can be fixed and the user can retry. All review endpoints use the existing loopback Host/Origin/JSON checks. Tests never publish a live review.

Browser draft persistence uses snapshot-scoped immutable comment versions (`:comment:<id>`), replacement links and separate deletion markers (`:deleted:<id>`). Legacy snapshot arrays remain readable. Storage events reconcile tabs without writing stale whole lists; concurrent edits of one version both survive. A successful review clears only the submitted version ids, preserving versions created or edited while submission is pending. Summary edits synchronize independently. GitHub context can be retried without refreshing, and reanalysis of the same snapshots refreshes the context.

Draft preview gathers versions across the PR's snapshot keys while retaining each original key and version ID. It checks readiness automatically on open and again before explicit submission; only ready, still-active versions are sent using fresh verified SHAs. Each explicit batch uses the largest ready prefix within 50 comments and 64 KiB of UTF-8 JSON; remaining versions and their summary stay saved. Original records are tombstoned only after success. The exact payload and originating versions are durably saved before submission, so an explicit retry after a lost response recovers the same receipt even when commits change. Web Locks serialize submission across tabs where supported.

Viewed markers use `flowreview:reviewed:<repository>:<PR>:<baseSha>:<headSha>` arrays. A new GitHub comparison verifies older candidates through refresh and applies only results for the displayed SHAs. Existing arrays, including an explicit empty array, preserve current decisions. Immutable per-PR decision events and per-comparison path lineage preserve explicit unmarks and later re-marks through future commits and verified renames. Events use unique keys and ordered lineage decisions, so interleaved tabs cannot overwrite another file's choice; legacy decision arrays remain readable. Historical checks use bounded batches; every batch must verify the displayed SHAs before any result is applied. In-flight user toggles and canceled/unmounted sessions cannot be overwritten by migration. Local comparisons never call the GitHub refresh endpoint.
